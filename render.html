render

Put a demo on a page: the bundle, a static page, show for notebooks, md for Markdown, and Demo for FastHTML.

One runtime draws a spec everywhere. A host element carries the spec as inert JSON, and the runtime mounts it:

<div data-rupaka><script type="application/json">{...spec...}</script></div>

The runtime boots on load and after each htmx swap. Nothing is templated into the script.

The bundle

bundle joins the core, the fns, the blocks and the boot script in a fixed order. There is no bundler and no build step.

js = bundle()

Each block style uses only the --rk-* vars for colour, so a demo takes the look of the page that holds it.

import re
for p in assets().css[1:]:
    cols = re.findall(r'(?:#[0-9a-fA-F]{3,6}\b|rgba?\(|hsl\()', p.read_text())
    test_eq((p.name, cols), (p.name, []))

three.js for scenes

A scene block draws in 3D with three.js. rupaka keeps a copy of three.js in rupaka/static/vendor/three/, so a scene works offline and loads nothing from a CDN.

item value
version three 0.185.0, from npm (three-0.185.0.tgz, integrity sha512-+yRrcRO2iZa8uzvNNl0d7cL4huhgKgBvVJ0njcTe8xFqZ6DMAFZdCKDP91SEAuj25bNAj7k1QQdf+srZywVK6w==)
files three.core.min.js and three.module.min.js, as npm gives them, with no change
licence MIT, in vendor/three/LICENSE
size about 750 KB

0.185.0 is the last release that has the minified files. The tests check the hash of each file, so a changed file fails at once.

The hashes of the two files, as sha256:

for f, h in THREE.files.items(): test_eq(hashlib.sha256((VENDOR/'three'/f).read_bytes()).hexdigest(), h)
assert 'MIT License' in (VENDOR/'three'/'LICENSE').read_text()

The two files are ES modules: the second one imports the first. A module cannot load from file:// or from a sandboxed srcdoc frame, and those are places where rupaka draws. So three_js joins the two files into one classic script. It changes only the import and export statements: an import becomes a read from the first file’s names, and an export becomes a return. The script puts the names on window.RupakaTHREE, and it does nothing when it runs a second time.

source

three_js

def three_js()->str:

three.js as one classic script that sets window.RupakaTHREE, made from the two vendored module files.

The script has no module statement left, and it exports the names that a scene uses.

t = three_js()
assert not re.search(r'(^|[;}])\s*(import|export)\s*[{*]', t) and 'from"./three' not in t
for k in ('WebGLRenderer', 'MeshToonMaterial', 'ExtrudeGeometry', 'DepthTexture', 'REVISION'): assert f'{k}:' in t, k
test_eq(bundle('three'), t)

A static page

page writes one self-contained HTML file: the runtime, the style, the specs, and abhyasa’s palette. The fonts argument picks how the page gets its fonts:

fonts what it does
'link' links Literata and Libre Baskerville from ./fonts (save copies them)
'embed' puts the fonts in the page as data URIs, about 160 KB more
'none' uses the system serif; for a sandboxed srcdoc frame, which cannot load files

source

font_css

def font_css(
    fonts:str='link', base:str='fonts/'
)->str:

The @font-face rules: linked from base, embedded as data URIs, or none.

page takes one spec or a list of specs. A list makes a gallery page with a rule between the demos. When a spec has a scene, the page also holds three.js.

source

page

def page(
    specs, title:str=None, fonts:str='link', lead:str=''
)->str:

One self-contained HTML document that draws specs, with no network.

A page loads nothing from the network: no src, href or url() points at http. (The SVG namespace string is not a request.) With fonts='none' it has no @font-face rule.

spec = dict(rupaka=1, id='t', title='T', state=dict(a=1), blocks=[dict(type='readout', text='{a}')])
p = page(spec)
assert not re.search(r'''(src|href)=["']?https?:|url\(\s*["']?https?:''', p)
assert '@font-face' in p and '@font-face' not in page(spec, fonts='none')
assert 'data:font/woff2;base64,' in page(spec, fonts='embed')
assert 'window.RupakaTHREE=' not in p
s3 = page(dict(rupaka=1, id='s', state={}, blocks=[dict(type='scene', blocks=[])]), fonts='none')
assert 'window.RupakaTHREE=' in s3 and not re.search(r'''(src|href)=["']?https?:|url\(\s*["']?https?:''', s3)

Notebooks: show

show(spec) returns an object that a notebook draws. It gives two mime types:

  • application/vnd.rupaka+json: the spec, for a frontend that knows rupaka (a later leela change).
  • text/html: the whole page with fonts='none'. leela, Jupyter and VS Code draw it in a sandboxed frame. This works in leela today.

Markdown: md

md(spec) writes a ```rupaka fence with readable JSON. A renderer that knows rupaka mounts it; others show the JSON as code. md(spec, frame=True) writes a ```{=html} fence that holds a sandboxed frame. leela draws this in a Markdown cell today, with no change to leela.

FastHTML: Demo and Assets

Demo(spec) is the host element as an FT component. Assets(prefix) gives the Link and the Script for a server that serves the bundle at prefix. A server that shows scenes also serves bundle('three') as three.js at the same prefix. The runtime loads it from there the first time that a scene mounts, and only then.

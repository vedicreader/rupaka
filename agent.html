agent

The demo agent: a model writes a spec from the block manifests, and code checks it before anyone sees it.

author(concept, ask) asks a model for one demo on a concept. The model writes data only: a JSON spec. It never writes code. Then the loop checks the spec, and gives the errors back to the model to fix:

  1. Parse the reply as JSON.
  2. validate the spec: types, binds, gates and the think rule.
  3. check the spec in headless Chrome: it draws, it plays, the keys work, the contrast is good.
  4. On errors, ask for a repair with only these errors. At most two repairs.
  5. Give up quietly: return None and log the errors. The caller keeps its text lesson.

ask(prompt, sp) is any function that returns text, as in abhyasa. The tests use a fake one.

The catalog

The prompt lists the blocks and fns from their manifests, so it never names a block that the runtime does not have.

source

The catalog names every block and every fn.

cat = catalog()
for n in [*manifests(), *fn_manifests()]: assert f'- {n}: ' in cat, n
print(cat[:600])

The system prompt

The system prompt says who the demo is for, gives the rules of a good demo, the shape of a spec, and the catalog. The demo is for a human learner, who can be new to the idea or know it well. A demo that only restates the definition teaches little. So the prompt asks for a concrete case first, a picture of it next, and the general rule last (concreteness fading).

assert 'Who this is for' in demo_sp() and 'Never only restate the definition' in demo_sp()

The user prompt

The user prompt describes the concept, the first error of the learner (if there is one), and two gallery demos as examples. The host can also give the learner’s level as a short text, for example “new to this” or “knows linear algebra”. With no level, the prompt does not change. near picks the gallery demos that share the most words with the concept. A long table in an example is cut to three rows.

The prompt that asks for a demo on concept, a dict with name, statement, subject and misconceptions.

c = dict(name='Reciprocal rank fusion', statement='Sum 1/(k + rank) over the lists.', subject='ml', misconceptions=['raw scores add'])
p = demo_prompt(c, 'You add the raw scores.', near(c))
assert 'first error: You add the raw scores.' in p and '"id": "reciprocal-rank-fusion"' in p

A level, when the host gives one, goes into the prompt. With no level, the prompt is the same as before.

test_eq(demo_prompt(c), demo_prompt(c, level=''))
assert 'level' not in demo_prompt(c)

The repair prompt

The repair prompt gives back the spec and only its errors. It tells the model to keep the teaching text, so a repair does not make the words more literal.

author

author runs the loop. It stamps the spec with the schema, an id and the concept slug. log, when given, gets one entry for each failed try. level goes on to demo_prompt.

source

author

def author(
    concept, ask, first_error:str='', examples:NoneType=None, check:bool=True, repairs:int=2, log:list=None,
    level:str=''
)->dict | None:

A checked demo spec on concept from the model ask, or None after repairs failed repairs. A spec with texts that are not plain (plain_errors) gets one repair; the plainer good spec stays.

Tests with a fake model

fake replies from a list, one reply for each call, and keeps the prompts.

from rupaka.spec import examples as block_examples
def fake(*replies):
    calls = []
    def ask(p, sp=''): calls.append(p); return replies[min(len(calls), len(replies)) - 1]
    ask.calls = calls
    return ask
good = json.dumps(block_examples()['gate'])

A good spec passes on the first call. The spec gets the concept slug.

a = fake(good)
s = author(dict(name='Sums', slug='sums'), a, check=False)
test_eq((s['concept'], len(a.calls)), ('sums', 1))

A spec with one error gets one repair. The repair prompt names the error.

broken = json.loads(good); del broken['blocks'][1]['after']
a, log = fake(json.dumps(broken), good), []
s = author('Sums', a, check=False, log=log)
assert s is not None and len(a.calls) == 2
assert 'gives away the answer of gate "sum"' in a.calls[1] and 'Fix only these errors' in a.calls[1]
test_eq(log[0]['tries'], 1)

author gives the level on to the prompt.

a = fake(good)
author('Sums', a, check=False, level='an expert')
assert "The learner's level: an expert." in a.calls[0]

Three bad replies give up quietly: the result is None, and the log has three entries.

log = []
test_eq(author('Sums', fake('not json', json.dumps(broken), '{}'), check=False, log=log), None)
test_eq(len(log), 3)

A model that fails gives up too, with no exception.

def down(p, sp=''): raise ConnectionError('no network')
test_eq(author('Sums', down, check=False), None)

A good spec with a text that is not plain gets one repair. The repair prompt names the problem, and the plainer spec comes back.

vague = json.loads(good); vague['ask'] = 'This departs from the usual rule.'
a, log = fake(json.dumps(vague), good), []
s = author('Sums', a, check=False, log=log)
test_eq((s['ask'], len(a.calls)), (json.loads(good)['ask'], 2))
assert '"departs from" is vague' in a.calls[1]

When the repair is not plainer, or does not pass the checks, the first good spec stays. The plain check never costs a demo.

test_eq(author('Sums', fake(json.dumps(vague)), check=False)['ask'], vague['ask'])
test_eq(author('Sums', fake(json.dumps(vague), 'not json', 'not json'), check=False)['ask'], vague['ask'])

With a browser, check runs too, and a good spec still passes in one call.

from rupaka.check import can_check
if can_check(): assert author('Sums', fake(good)) is not None

Plain English

A host can make a text plain with plain. When plain_why finds problems in a text, plain asks the model once to write it again, and names the problems. It keeps the new text only when it has fewer problems and keeps each number, each $...$ maths span and each code span. Else the old text stays. A text that passes costs no call. A dict of texts costs at most one call for all the texts that fail.

source

plain_prompt

def plain_prompt(
    x, why
)->str:

The prompt that asks the model to write x (a text, or a dict of texts) again; why has the problems (of each key, for a dict).

keeps says whether a new text keeps the maths, the code and the numbers of the old text, and each text of keep that the old text has.

source

keeps

def keeps(
    old:str, new:str, keep:tuple=()
)->bool:

Whether new has each maths span, code span, number and keep text of old.

assert keeps('Add $a+b$ to 3 apples.', 'You have 3 apples. Add $a+b$.')
assert not keeps('Add $a+b$ to 3 apples.', 'You have 4 apples. Add $a+b$.')
assert not keeps('Run `f(x)`. Check: why?', 'Run f(x). Check: why?') and not keeps('Check: why?', 'Why?', keep=['Check:'])

plain takes a text or a dict of texts. A new text must also look like a text: not empty, not JSON in place of words, and not less than a third of the old length, and not more than about three times it.

source

plain

def plain(
    ask, x, terms:tuple=(), keep:tuple=()
):

x (a text, or a dict of texts) in plain English: each text that fails plain_why is written again by ask in one call, and kept only when it is better.

A text that passes makes no call. The owner’s bad question gets one call, and the plain version comes back.

good_q = 'In a DDPM, the amount of noise at each step is set before training. Suppose the network learns this amount instead. Which DDPM rule does this break? Why?'
bad_q = 'You train a DDPM on recordings of rain. You ask the network to learn the noise recipe as it trains. Why does this depart from a DDPM simplifying assumption?'
a = fake(good_q)
test_eq((plain(a, good_q), len(a.calls)), (good_q, 0))
test_eq((plain(a, bad_q), len(a.calls)), (good_q, 1))
assert '"recipe" is a nickname' in a.calls[0]

A new text that drops a number or the maths, or that is not better, is not kept. A model that fails keeps the old text too.

q = 'The loss is $L = (y - 3)^2$; it uses 3 as the target and you facilitate the fit.'
test_eq(plain(fake('The loss is $L$. It uses a target.'), q), q)
test_eq(plain(fake(q), q), q)
test_eq(plain(down, q), q)
new = 'The loss is $L = (y - 3)^2$. It uses 3 as the target. You help the fit.'
test_eq(plain(fake(new), q), new)

A dict sends only the texts that fail, in one call, and keeps the others as they are.

a = fake(json.dumps(dict(q=good_q)))
test_eq(plain(a, dict(q=bad_q, o='Yes.')), dict(q=good_q, o='Yes.'))
test_eq(len(a.calls), 1); assert '"o"' not in a.calls[0]

A live run

A live run uses a real model, so it is not part of the tests. With the rishi package and its model claude/sonnet, it looks like this:

from rishi import Chat, resp_text
def ask(p, sp=''):
    chat = Chat('claude/sonnet', sp=sp)
    try: return resp_text(chat(p))
    finally: chat.close()
log = []
spec = author(dict(name='Guṇa sandhi', statement='a or ā before i, u or ṛ gives e, o or ar.', subject='sanskrit'), ask, log=log)

The first live run (26 October 2026, claude/sonnet, three concepts: guṇa sandhi, cosine similarity and binary search):

concept result model calls
guṇa sandhi passed on the first try 1
cosine similarity passed after one repair: a point showed the answer before the gate, and the think rule caught it 2
binary search passed on the first try 1

So 3 of 3 passed, 2 of them on the first try. One spec put {n} in its plain-text ask. The check could not see it, so validate now refuses a template in a plain-text prop.

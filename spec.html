spec

Build a demo spec in Python, check it, and move an old spec to the new schema.

A demo is one JSON object: the spec. It lists blocks, a small state, derived values and data tables. This module reads the block and fn manifests, gives a builder for each block, and checks a spec with validate.

validate enforces the think rule: a block that shows a value which a gate’s answer depends on must wait for that gate. So the learner always predicts before the demo shows the result. An explainer ("mode": "learn") is the one spec with no gate: it shows a thing at once, with no prediction step.

Manifests

Each block is a folder in rupaka/blocks/, with a block.json manifest. Each fn has a manifest in rupaka/fns/. A manifest gives the purpose in one line, the props with their types, and the keys. The validator and the agent prompt read the manifests, so they never drift from the code.

The expr grammar

expr holds a formula in a tiny safe grammar: numbers, names, + - * / ^, parentheses and a few math functions. The runtime parses it in JavaScript. This is the same parser in Python, so validate can check a formula and run it. There is no eval in either one. A name must be a state key, a constant or one of the functions.

_safe turns a math error into the value JavaScript gives, so both sides agree: nan or an infinity.

parse_expr returns a function of a dict of values, and the set of names that the formula reads.

source

parse_expr

def parse_expr(
    src:str, # the formula
    fns:dict=None, # more functions by name, on top of `EXPR_FNS`
):

Parse a formula. Return (f, names): f(env) gives a number, and names are the values it reads.

2*x^2 - 1 at x = 3 is 17. The power binds before the minus sign, so -x^2 at x = 3 is −9.

f, ns = parse_expr('2*x^2 - 1')
test_eq(f(dict(x=3)), 17)
test_eq(ns, {'x'})
test_eq(parse_expr('-x^2')[0](dict(x=3)), -9)
test_eq(parse_expr('max(a, b) + floor(7/2)')[0](dict(a=1, b=4)), 7)

Names that reach into objects, calls of unknown functions, and a second statement are refused.

for bad in ('constructor', '__proto__', 'alert(1)', 'x;y', 'x.y', '2 +'): test_fail(lambda: parse_expr(bad)[0](dict(x=1, y=2)), contains='expr')

run

def run(
    spec, state:dict=None

The state of spec after the derive list, from its opening state or from state.

The fused scores of the two spike lists at k = 60: B is first, because it is in both lists.

sp = dict(state=dict(bm25=list('ACEB'), vec=list('DFGB'), k=60), derive=[rrf(['bm25', 'vec'], 'k', 'fused')], blocks=[])

test_eq(run(sp, {**sp['state'], 'k': 1})['fused'][0]['id'], 'A')

sample takes a formula at each tick of a rate. At 4 ticks per unit over [0, 1], there are 5 points.

sg = dict(state=dict(f=1, fs=4), derive=[sample('sin(2*pi*f*t)', {'t': [0, 1]}, 'fs', 'dots')])
dots = run(sg)['dots']
test_eq([p['x'] for p in dots], [0, .25, .5, .75, 1])
test_close(dots[1]['y'], 1)

dft gives the strength of each whole frequency. A sine of amplitude 2 at 3 Hz is one bar of 2 at 3, and zero in the other bins.

sd = dict(state=dict(a=2), derive=[dft('a*sin(2*pi*3*t) + 0.5', {'t': [0, 1, 32]}, 'sp', upto=8)])
sp = run(sd)['sp']
test_eq([b['id'] for b in sp], [str(k) for k in range(9)])
test_close(sp[3]['value'], 2)
test_close(sp[0]['value'], 0.5)
assert all(b['value'] < 1e-9 for k, b in enumerate(sp) if k not in (0, 3))

A rate under twice the frequency makes an alias. A 5 Hz sine sampled at 8 Hz has the same points as a 3 Hz sine with its sign flipped.

al = lambda f, fs: [p['y'] for p in run(dict(state=dict(f=f, fs=fs), derive=[sample('sin(2*pi*f*t)', {'t': [0, 1]}, 'fs', 'd')]))['d']]
assert all(abs(a + b) < 1e-9 for a, b in zip(al(5, 8), al(3, 8)))

softmax at a high temperature makes the shares more equal.

sp = dict(state=dict(z=[2, 1, 0]), derive=[softmax('z', 'p', t=1), softmax('z', 'q', t=2)], blocks=[])
st = run(sp)
test_close(st['p'][0]['value'], 0.6652, eps=1e-4)
assert st['q'][0]['value'] < st['p'][0]['value']

field runs a formula on each cell of an n x n grid. Row i and column j go from 0 to n − 1. This formula fades a ramp into noise as t goes from 0 to 1000:

DIFF = 'sqrt(1 - t/1000) * (i + j)/30 + sqrt(t/1000) * noise(i, j)'
def fld(f, t=500, seed=7, n=16): return run(dict(state=dict(t=t), derive=[field(f, 'img', n=n, seed=seed)]))['img']
img = fld(DIFF)
test_eq((len(img), len(img[0])), (16, 16))
[round(v, 3) for v in img[0][:4]]

The same seed gives the same field, and another seed gives another field. At t = 0 there is no noise, so each cell is (i + j) / 30.

test_eq(fld(DIFF), img)
assert fld(DIFF, seed=8) != img
test_eq(fld(DIFF, t=0)[3][4], 7/30)
fld(DIFF, t=0)[3][:4]

validate

validate(spec) returns a list of errors. Each error has a path and one sentence, for example blocks[3].bind: "fused" is not in state or derive. An empty list means the spec is good. It checks, in order:

  1. The shape: the schema number, the top-level keys, the mode, and a list of blocks.
  2. Each derive: the fn exists, its props have the right types, and it reads only keys that come before it.
  3. Each block: the type exists, its props have the right types, the required props are there, and each bind names a key. Each after and each lock names a gate, and no gate waits for itself. A block above its gate can wait for it, for example a mark on a figure.
  4. A demo has at least one gate, and an explainer has none (see below). Each gate: its answer resolves on the opening state and is one of its options. A gate whose answer a live control can change names its inputs with context.
  5. The think rule (below).
  6. Text: each sentence has at most 20 words.

First, the prop types. A scene adds four: vec3 ([x, y, z]), vec3key ([x, y, z], where an item can be a state key), nums (one to three sizes) and texts (lines of text). _reads gives the keys that a value of a type reads, so the think rule can follow them.

_props checks the props of one block or one derive entry against its manifest. A prop with min or max in its manifest must be in that range. A prop with of must be one of the values in that list. It returns the keys that the entry reads.

The think rule

The answer of a gate has a root key: for fused.0.id, it is fused. A block must wait for the gate when it reads a key that gives the answer away:

  • the root key itself;
  • each derived key that the root is computed from (raw inputs are the question, so they stay visible);
  • each derived key that is computed from any of these.

A fixed answer ({"is": ...}) has no root key, so the gate names the keys that give it away in hides. A block waits for the gate when it, or a block that holds it, has after set to that gate, or to a gate that itself waits for it.

Plain English

The texts must also be plain: ASD-STE100 Simplified Technical English at a US grade 9 reading level. plain_why is a cheap check in code, so a host can find a hard text before the learner sees it. It finds four kinds of problem: a sentence of more than MAX_WORDS words, a reading grade over MAX_GRADE, a semicolon, and a word from a short list of vague words or nicknames. No package in the environment gives a reading grade, so the count is written here. The grade is the Flesch-Kincaid grade, with a rough count of syllables.

source

syllables

def syllables(
    w:str
)->int:

A rough count of the syllables of the English word w: the groups of vowels, less a silent end.

A silent end does not count: “trained” has one syllable, and “table” has two.

test_eq([syllables(w) for w in ('trained', 'table', 'network', 'assumption', 'free', '42')], [1, 2, 2, 3, 1, 1])

Maths in $...$, code, a {path}, a name in quotes and the terms (names of the subject, such as the name of the concept) each count as one short word. Long technical names do not make the grade high.

source

grade

def grade(
    s:str, terms:tuple=()
)->float:

The Flesch-Kincaid grade of the text s, with terms as short words.

A plain text has a low grade. A text full of long formal words has a high grade. A long term counts as one short word when it is in terms.

assert grade('The cat sat on the mat. It was warm.') < 3
assert grade('Considering the multifaceted implications of compounding over extended periods, elucidate why a debt grows nonlinearly.') > 15
long = 'Backpropagation through time unrolls the network.'
assert grade(long, ['backpropagation through time']) < grade(long)

plain_why gives each problem as a sentence that a model can act on. The grade counts only for a text of 12 words or more: on a short label, the grade says little. A phrase of two to four common words in quotes reads as a made-up name, so it is a problem too.

_check_blocks does the block checks, the gate checks and the think rule. An explainer has no gate, so the think rule has nothing to check. Its blocks cannot wait for a gate or lock to a gate, and the error says why. It gives each scene to _check_scene (below).

_check_gate checks one gate: its answer, its options, its context, and the think rule for its answer.

Scenes

A scene holds body, force, label3d and shot blocks. The manifests check each prop alone. _check_scene checks how the parts fit together:

  • Each body id is used one time. A body that is in another body names a body above it, so a body cannot hold itself.
  • A size has the right count of numbers for its kind.
  • A force or a label that is on a body names a body of the same scene.
  • A shot name is wide, side, front, top or close:<body id>. A shot that binds a key names a state key with a good shot name, so a host can set it.
  • A part with a step is in a scene with bind, and the step is in the range of the steps lines.
  • The step key is a state key with an int from 1. There are at most 8 steps, 40 bodies, 12 forces and 12 labels, and a chip has at most 60 characters.

Flows

A flow is small: two to five nodes and at most eight arrows, as in abhyasa’s board. Each node has a short id and at most 32 characters of text. Each arrow joins two other nodes one time, and its words are at most 3 words and 30 characters.

_check_keyframes wants keys that go up in time, with known curves. _check_stage checks a timeline (its range and its markers) and a layer that a person drags: each dragged axis needs a state key to write.

def stage_errs(**kw): return validate(demo('s', state=dict(t=0, x=1), mode='learn', blocks=[
    _b('layers', blocks=[_b('layer', art='boat', x='x', drag=kw.pop('drag', 'x'))]), _b('timeline', bind='t', **kw)]))
test_eq(stage_errs(), [])
test_eq(stage_errs(drag='xy'), ['blocks[0].blocks[0].y: a layer that drags in y needs "y" to be a state key'])
test_eq(stage_errs(markers=[dict(t=120, label='Late')]), ['blocks[1].markers[0].t: must be from 0 to 100'])
test_eq(len(stage_errs(markers=[dict(t=1)])), 1)
bad = demo('k', state=dict(t=1), derive=[keyframes('t', [[0, 1], [0, 2]], 'v')], blocks=[readout('{v}')])
test_eq(validate(bad), ['derive[0].keys: the times must go up'])

Tests for validate

A good demo has no errors.

good = demo('sum', 'Sum', state=dict(a=2, b=3), derive=[expr('a + b', 'sum')],
            blocks=[gate('s', 'What is {a} + {b}?', [4, 5, 6], 'sum'), readout('{a} + {b} = {sum}', after='s')])
test_eq(validate(good), [])

A readout of the sum before the gate fails the think rule, with the path of the readout.

bad = deepcopy(good); del bad['blocks'][1]['after']
test_eq(validate(bad), ['blocks[1]: this readout shows "sum", which gives away the answer of gate "s"; add "after": "s"'])

An unknown block, an unknown fn, an unknown prop and a missing prop each fail with a path.

test_eq(errs_of(blocks=[*good['blocks'], dict(type='dial')])[0][:23], 'blocks[2].type: "dial" ')

A bind to a key that is not in the state fails. So does an after that names no gate.

assert 'blocks[2].bind: "k" is not in state or derive' in errs_of(blocks=[*good['blocks'], slider('k')])
test_eq(errs_of(blocks=[readout('{sum}', after='t'), good['blocks'][0]]), ['blocks[0].after: "t" is not a gate', 'blocks[0]: this readout shows "sum", which gives away the answer of gate "s"; add "after": "s"'])

A text prop that the manifest marks rich (a caption text, a gate prompt and its context) and the ask can have bold. In any other text, or the title, the stars show as they are, so validate refuses them. Stars in maths do not count.

assert has_bold('a **sweet** item') and not has_bold('$a**b$ and a lone **') and has_bold('**{n}** is even')
test_eq(errs_of(ask='Ask for something **sweet**.', blocks=[gate('s', 'Is **{a}** first?', [4, 5, 6], 'sum', context='For **{a}**:'), *good['blocks'][1:]]), [])

test_eq(errs_of(blocks=[good['blocks'][0], readout('{a} is **big**', after='s')]), ['blocks[1].text: is plain text, so **bold** shows as it is; remove the stars, or put the text in a caption'])

A field needs an n from 1 to 64 and an int seed. A bad formula fails with its expr: error. The names i, j and noise need no state key.

fd = demo('fd', state=dict(t=500), derive=[field(DIFF, 'img', n=16, seed=7)],

A gate answer must be one of its options. A demo needs a gate.

A live control that changes the answer needs a context on the gate, so the verdict names its inputs.

Explainers

An explainer shows a thing at once, for example a 3D scene that builds one step at a time. It has no gate and no prediction step. Only "mode": "learn" makes a spec an explainer. The default mode is predict, and then a spec with no gate is still refused. All the other checks still run. The runtime shows a small “Explainer” label above the title.

A scene with no gate passes as an explainer:

ex = demo('box', 'A box', mode='learn', state=dict(step=1), blocks=[scene(body('b', 'box', [1, 1, 1]), bind='step', steps=['A box.'])])
test_eq(validate(ex), [])

With no mode, the same spec is refused with the usual message. A mode that is not predict or learn is refused.

test_eq(validate({k: v for k, v in ex.items() if k != 'mode'}), ['blocks: needs at least one gate: the learner predicts first'])
test_eq(validate({**ex, 'mode': 'learning'}), ['mode: "learning" is not a mode; use predict or learn'])
test_eq(validate({**good, 'mode': 'predict'}), [])

An explainer cannot have a gate, and its blocks cannot wait for a gate. The other checks still run, for example on a text that reads a missing key.

test_eq(validate({**good, 'mode': 'learn'}), ['blocks[0]: an explainer has no gate; remove the gate, or remove "mode": "learn"'])
test_eq(validate({**ex, 'blocks': [*ex['blocks'], readout('{a}', after='s')]}), ['blocks[1].text: "a" is not in state or derive', 'blocks[1].after: "s" is not a gate; an explainer has no gate, so remove "after"'])

Steps in an explainer

A part of an explainer can show from a step, for example "step": 2. The host sets the state key step with Rupaka.set(host, {step: n}). Then each part with a step of n or less shows, and draws in from the left. A part with no step shows at all steps. Here the first readout shows at step 1, and the stack shows at step 2:

sx = demo('steps', 'Steps', mode='learn', state=dict(step=1), blocks=[readout('One', step=1), stack(readout('Two'), step=2)])
test_eq(validate(sx), [])

A step needs the state key step, an int from 1, and an explainer. A demo that predicts first shows each part when its gate opens, not by step.

need = 'needs the state key "step" as an int from 1, so that the host can set the step'
test_eq(validate({**sx, 'state': {}}), [f'blocks[0].step: {need}', f'blocks[1].step: {need}'])
test_eq(validate({**sx, 'blocks': [readout('One', step=0)]}), ['blocks[0].step: must be an int from 1'])
assert 'blocks[2].step: only an explainer shows its parts by step' in validate({**good, 'blocks': [*good['blocks'], caption('Go on.', step=2)]})[0]

Some blocks have a step of their own: the size of one move of a slider, or the step of a scene part. They keep that meaning. To show one of them by step, put it in a stack with the step. The runtime knows these blocks from a list, and this test keeps the list equal to the manifests:

own = re.search(r'ownStep = new Set\(\[([^\]]*)\]', (PKG/'static'/'rupaka.js').read_text())[1]
test_eq(set(re.findall(r"'(\w+)'", own)), {n for n, m in manifests().items() if 'step' in m.props})

Ask about this

Each demo shows a small “Ask about this” control at its end. The learner uses it to ask the tutor about what the demo shows now. The demo then sends the rk-ask event to the host page (see rupaka.render). The control is on by default, so a spec does not need a key for it. To turn it off, a spec sets "askable": false. The key must be true or false:

test_eq(validate({**good, 'askable': False}), [])
test_eq(validate({**good, 'askable': 'no'}), ['askable: is true or false; false hides the Ask about this control'])

Pairs

A pair is one row of a worked example: input cells, an arrow and the answer. A list of pairs builds a table of practice examples, one row at each step:

px = demo('pairs', mode='learn', state=dict(step=1), blocks=[pair(['[18]'], '47', heads=['Input', 'Target'], step=1), pair(['[18, 47]'], '56', step=2)])
test_eq(validate(px), [])

A pair has one to six cells, and heads has two labels. A manifest prop with least or most limits the count of items in a list:

test_eq(validate({**px, 'blocks': [pair([], '1')]}), ['blocks[0].cells: needs 1 to 6 items'])
test_eq(validate({**px, 'blocks': [pair(['a'], '1', heads=['x'])]}), ['blocks[0].heads: needs 2 items'])

Tests for scenes

A small scene: a box and a cone, a force on the box, a label, and a shot that a host can set. The force shows the answer, so it waits for the gate.

sc = demo('lift', 'Lift', state=dict(step=1, cam='wide', w=4), derive=[expr('w * 2', 'up')],
          blocks=[gate('g', 'What is twice {w}?', [6, 8], 'up'),
                  scene(body('base', 'box', [2, 1, 2]), body('top', 'cone', [0.6, 1], [0, 1, 0], inside='base'),
                        force([0, 1, 0], 'up', on='base', at=[0, 1.5, 0], label='lift, {up}', after='g'),
                        label3d('the base', on='base'), shot(bind='cam'), shot('close:top', step=2),
                        bind='step', steps=['A box with a cone.', 'Look at the cone.'])])
test_eq(validate(sc), [])
test_eq(shots(sc), ['wide', 'side', 'front', 'top', 'close:base', 'close:top'])

A helper puts one bad part in the scene, and gives the errors.

def scene_errs(i, **kw):
    s = deepcopy(sc); part = s['blocks'][1]['blocks'][i]
    for k, v in kw.items():
        if v is None: part.pop(k, None)
        else: part[k] = v
    return list(validate(s))

An unknown body kind, a force on a missing body, and a bad shot name are each refused with a clear sentence.

test_eq(scene_errs(0, kind='pyramid'), ['blocks[1].blocks[0].kind: "pyramid" is not one of: box, cylinder, cone, sphere, capsule, torus, group'])
test_eq(scene_errs(2, on='wing'), ['blocks[1].blocks[2].on: "wing" is not a body in this scene; use one of: base, top'])
test_eq(scene_errs(5, name='close:wing'), ['blocks[1].blocks[5].name: "wing" is not a body in this scene, so "close:wing" is not a shot'])
test_eq(scene_errs(5, name='zoom'), ['blocks[1].blocks[5].name: "zoom" is not a shot; use wide, side, front, top or close:<body id>'])

A bound shot must start with a good name. A body cannot be in a body below it, and a size needs the right count of numbers.

bad = deepcopy(sc); bad['state']['cam'] = 'far'

test_eq(scene_errs(0, **{'in': 'top'}), ['blocks[1].blocks[0].in: "top" is not a body above this one in the scene'])
test_eq(scene_errs(1, size=[1, 2, 3]), ['blocks[1].blocks[1].size: a cone needs 2 numbers'])
assert 'must be [x, y, z]' in scene_errs(1, at=[0, 1])[0]

A part goes only in a scene. A part with a step needs the step key, and the step must be in the range of the lines.

test_eq(errs_of(blocks=[*good['blocks'], body('b', 'box')]), ['blocks[2]: a body must be inside a scene'])

Streaming: append

A server can send a spec one block at a time, so the first part shows in a few seconds. The page mounts the start of the spec, then adds each block with Rupaka.append(host, block). append does the same in Python: it adds the block only when the grown spec passes validate. With into, the block goes at the end of a stack or a row, for example into='blocks.0'.

source

append

def append(
    spec:dict, block:dict, into:str=None
)->fastcore.foundation.L:

Add block to spec at the end, or in the stack or row at the path into, when the spec stays good. The errors of the grown spec.

A good block goes in, and the earlier blocks stay:

pn = demo('panel', mode='learn', state=dict(step=1), blocks=[stack(readout('One', step=1))])
test_eq(append(pn, readout('Two', step=2)), [])
test_eq([b['type'] for b in pn['blocks']], ['stack', 'readout'])
test_eq(append(pn, caption('Three'), into='blocks.0'), [])
test_eq([b['text'] for b in pn['blocks'][0]['blocks']], ['One', 'Three'])

A bad block, or a place that is not a stack or a row, gives the errors, and the spec does not change:

test_eq(append(pn, readout('{zz}')), ['blocks[2].text: "zz" is not in state or derive'])
test_eq(append(pn, readout('x'), into='blocks.1'), ['blocks.1: is not a stack or a row'])
test_eq(len(pn['blocks']), 2)
